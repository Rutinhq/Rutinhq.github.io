# GTM OS

Sources: https://www.rutinhq.com/gtm-os · https://docs.rutinhq.com/catalog/gtm-os/

A cold B2B prospecting system installed in the client’s team — not a rented SDR that dies when the contract ends. Change language, filters, and angle; keep the core.

For whom: Founder / CEO or B2B ops lead; already sells; bottleneck is a repeatable pipeline; ICP-filtered cold email; first run always cold.

Not for: Pure ecom / B2C; “just run ads”; enterprise RFP with no outbound owner; guaranteed-N-meetings buyers.

How (M0–M7, no skip): sector research → ICP + validation → messaging framework → sales playbook + gate → campaign activation → crawl / analysis → weekly KPIs → close + scale to the next vertical. Validate one vertical before scaling.

Roles: Commercial Architect designs and gates. Outbound Specialist runs sequences and classifies replies. HoD validates technical fit.

Reply protocol: classify before answering (open / question / referral / OOO / not interested / silence). One bump on silence, then discard. Discovery: the lead describes their process — no feature pitch.

Outcomes: outbound pipeline the team can run; ICP with checkable criteria; sequences + SOP so the system survives without the agency.

What it is not: ads or social agency; a wiki for someone else’s SaaS; a dump of lead lists / CRM / APIs; a promise of N meetings.
